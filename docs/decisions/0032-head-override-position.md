# ADR-0032: ページの `<title>` と `<meta charset>` と `<meta name="viewport">` は、レイアウトの同じ種類の要素の位置に入る

- 状態: 採択（ADR-0019 / ADR-0023 を補う。置換はしない）
- 日付: 2026-11-02

## 文脈

ページとレイアウトの合流（ADR-0019）では、`<title>`、`<meta charset>`、`<meta name="viewport">` を、ページとレイアウトにまたがって 1 つに揃える。ページ側に同じ種類の要素があれば、ページ側の先頭を残す（ADR-0023）。一方、ページの `<head>` の子は、レイアウトの `<head>` の末尾へ移る。

この 2 つが重なると、残したページ側の要素は、レイアウトの `<head>` の末尾に出る。レイアウトが `<meta charset>` を先頭に置き、その後に `<meta name="color-scheme">` などを並べていても、出力の `<meta charset>` はそれらより後ろに来る。見本サイトの出力では、`<meta charset>` が `<meta name="color-scheme">` の後ろにあった。

HTML 仕様は、文字コードの宣言を含む要素を、文書の先頭 1024 バイト以内に完全に収めるよう求める（[Specifying the document's character encoding](https://html.spec.whatwg.org/multipage/semantics.html#charset)）。レイアウトの `<head>` が大きいと、末尾へ移った `<meta charset>` はこの範囲の外へ出うる。

## 決定

- `<title>`、`<meta charset>`、`<meta name="viewport">` の重複除去は、式の評価の後に行う。レイアウトへの合流と式の評価を終えた文書の `<head>` で、参照の展開より前に 1 回だけ行う。合流では、ページの `<head>` の子をレイアウトの `<head>` の末尾へ移すだけにし、重複を除かない
- 候補は、評価の後の `<head>` の中にある同じ種類の要素のうち、どの `<template>` の中身にもないものとする。偽の `<template if>` や空の `<template each>` で消えた要素は候補にならず、評価で残った要素は候補になる。素の `<template>` の中（ADR-0023）と、`<template html>` の値から生まれた `<template>` の中は候補にしない
- 残す要素は、優先を書いたファイルで決める。その要素を書いたファイル（ADR-0035）が、ページ、内側のレイアウト、外側のレイアウトの順に前にある要素を残す。同じファイルの中では、文書順で先の要素を残す。書いたファイルの記録がない要素（`<template html>` の値から生まれた要素）は、ページが書いたものとみなす
- 位置は、文書順で最初の候補の位置とする。残す要素がその最初の候補でなければ、残す要素を最初の候補と置き換える。合流でページ側の要素はレイアウト側の要素より後ろに入るので、レイアウトに同じ種類の要素が評価の後に残っていれば、残すページの要素はレイアウトの位置に入り、ページの値がレイアウトの位置を引き継ぐ。レイアウトに残っていなければ、ページの `<head>` の他の子と一緒に末尾へ移った位置のままになる
- ADR-0023 の「ページ側の先頭を残して他を全部消す。ページになければレイアウト側の先頭」は、評価の後の先頭と読む。評価の前に書かれた位置や、`<template if>` の中にあるかどうかでは選ばない
- 空白は ADR-0030 に合わせる。残す要素は最初の候補の直前の空白をそのまま使い、他の候補は直前の空白ごと消す
- 重複除去はページとレイアウトの合流の規則（ADR-0019）である。レイアウトへ合流しないページでは行わない。参照の展開より前に行うので、テンプレートの出力の要素も候補にしない

## 理由

- 式の評価より前に残す要素を決めると、評価で消える要素を残し、評価で残る要素を消しうる。ページが `<template if="t"><title>{{ t }}</title></template>` とだけ書き、`t` が空なら、評価の前にはページの `<title>` を残してレイアウトの `<title>` を消し、評価がページの `<title>` も消して、出力に `<title>` がなくなる。評価の後なら、出力に残る要素だけを比べられる
- レイアウトが `<template if="x">` と `<template if="!x">` に分けて書いた要素も、評価の後にはどちらか一方だけが残る。評価の前に選ぶと、前の方だけを残して後ろを消し、`x` が偽のときに要素がなくなる
- 優先を書いたファイルで決めれば、合流の後の木のどこにあるか、`<template if>` の中に書いたかどうかによらず、ページの値がレイアウトの値に勝ち、内側のレイアウトが外側のレイアウトに勝つ。書いたファイルは、エラーの報告のためにすでにノードへ結び付けてある（ADR-0035）
- 位置を文書順で最初の候補にすると、レイアウトの書き手が決めた位置が保たれる。HTML 仕様は、文字コードの宣言を文書の先頭 1024 バイト以内に完全に収めるよう求める。レイアウトの書き手が `<meta charset>` を `<head>` の先頭に置けば、ページが自分の `<meta charset>` を書いても、出力の `<meta charset>` は先頭に残る
- レイアウトは文書の骨格を決める側で、ページは値を差し替える側である。ページが値を差し替えても、要素の並びはレイアウトに書いたとおりになる
- 3 種類に同じ規則を当てるので、`<meta charset>` だけの特別扱いが要らない

## 却下した選択肢

- `<meta charset>` だけを常に `<head>` の先頭へ移す: 1024 バイトの要件は満たすが、レイアウトの書き手が決めた順序を崩す。`<meta charset>` だけの特別扱いが増える
- 何もしない: 出力の `<meta charset>` が、レイアウトの他の要素より後ろに出る。レイアウトの `<head>` が大きいと、先頭 1024 バイトの外へ出うる
- 合流のたびに、式の評価より前に重複を除き、`<head>` の直下の候補を `<template if/each/html>` の中の候補より先に選ぶ（以前の実装）: 評価で消える要素を残し、評価で残る要素を消しうる。`<template if>` の中のページの要素は、レイアウトの位置を引き継げない

## 影響

- 見本サイトの出力では、`<meta charset>` が `<head>` の先頭にある。`<meta name="viewport">` と `<title>` も、レイアウトに書いた位置に入る
- ページが `<template if>` の中にだけ `<title>` を書くと、条件が偽ならレイアウトの `<title>` が残る。条件が真なら、ページの `<title>` がレイアウトの `<title>` の位置に入る
- ページが `<head>` の直下と `<template if>` の中に同じ種類の要素を書き、評価の後に両方が残れば、文書順で先の要素が残る。`<head>` の直下の要素を先に選ぶことはしない
- レイアウトの `<template if>` の中の要素も、評価の後に残れば位置の基準になり、ページの要素がその位置に入る。評価で消えれば、位置の基準にならない
- レイアウトが `<template if="x">` と `<template if="!x">` に分けて書いた要素は、`x` の真偽どちらでも 1 つだけ残る。以前の実装の既知の制約（前の方だけが残り、`x` が偽のときは出力に出ない）はなくなる
- 多段のレイアウトでは、ページになければ内側のレイアウトの要素が残り、外側のレイアウトに同じ種類の要素があればその位置に入る
- `<meta name="description">` のように 1 つに揃えない要素は、従来どおりレイアウトの `<head>` の末尾へ移る
- レイアウトが `<meta charset>` を先頭に置かなければ、出力でも先頭には来ない。1024 バイトの要件を満たす位置に置くのは、レイアウトの書き手である
- レイアウトへ合流しないページと、テンプレートが `<head>` に出した要素では、従来どおり 1 つに揃えない
