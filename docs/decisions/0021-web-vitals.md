# ADR-0021: Web Vitals の検査を 2 段階で入れる

- 状態: 採択
- 日付: 2026-09-12

## 文脈

「JS を足さない」「アップグレードギャップを無害化する」は、Web Vitals で言えば INP と CLS がそのまま指標になる。思想を数値で検証する装置として検査を入れる。

## 決定

**ライブラリ側（コンポーネント単位）**

- vitest のブラウザモードで `PerformanceObserver` の `layout-shift` を観測し、JS なしの描画から Custom Element の定義が到着するまでの累積レイアウトシフトが 0 であることを、各コンポーネントのテストで要求する。ADR-0004 の「壊れて見えない」を数値で強制する
- コンポーネントごとの CSS と JS のバイト数に上限を置く。上限値は最初のコンポーネントを作った時点で決める

**見本サイト側（ページ単位）**

- GitHub Pages 用のビルド後に Lighthouse CI を実行し、LCP、CLS、TBT（INP の実験室での代替）、総転送量に予算を設定する。閾値を越えたら CI を落とす
- 実際の利用者からの計測（`web-vitals` ライブラリによる送信）は行わない。送信先のサーバーが要り、サイトに JS を足すことになるため。ADR-0017 の未決定事項（Workers + Hono）が実現したら再検討する

## 順序

- CLS テストは最初の縦切り（ADR-0007、accordion）に含める。accordion は JS を持たないので期待値 0 が自明に通り、テストの型だけ先に作れる
- Lighthouse CI は見本サイトを Pages に出す時点で足す
