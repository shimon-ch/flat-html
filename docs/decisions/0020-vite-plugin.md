# ADR-0020: flat-html は Vite プラグインとして作る

- 状態: 採択（ADR-0002 の「核は Vite に依存しない API と CLI」を置換）
- 日付: 2026-09-10

## 文脈

ADR-0002 は、核を Vite から独立させ、Vite プラグインを薄い皮にすると決めた。その根拠は「他のビルド環境で使う道を閉じない」「テストを Vite なしで書ける」だった。前者はまだ存在しない要件への備えであり、「具体的な必要が出るまで足さない」に反する。フロントエンドのビルド基盤は Vite に収束しつつあり、開発基盤も Vite+ に決めている。

## 決定

- flat-html は Vite プラグイン `@flat-html/vite` として作る。独立した核パッケージと CLI は作らない
- 展開と集約の本体は「HTML 文字列と探索先を受け取り、HTML 文字列を返す純粋な関数」として、プラグインの内側に置く。Vite の hook（`transformIndexHtml` の `order: 'pre'`）はその関数を呼ぶだけにする
- 純粋関数のテストは Node 環境で書く。コンポーネントのテスト（ADR-0009）はブラウザモードのまま
- Rust 化は napi 経由でこの純粋関数を差し替える形で行い、Vite との接点は変えない
- Vite は薄く使う。触れるのは公開されたプラグイン hook だけとし、Vite の内部 API や Rolldown の非公開の仕組みには依存しない

## 理由

- Vite には開発サーバー、ファイル監視、資産の解決とハッシュ付与、モジュールグラフが最初からある。核を独立させると、これらとの橋渡しを自分で書くことになる
- パッケージを分けないことと関数を分けないことは別。純粋関数として分けておけば、テストの容易さと Rust 化の範囲の明確さは、パッケージの独立なしに得られる
- 趣味のプロジェクトであり、乗り換えの備えより開発の利点を優先する

## 引き受ける制約

- 別のビルド基盤（Rspack など）への移植は無償ではない。`unplugin` は `transform` や `load` は包むが、`transformIndexHtml` は Vite 固有。必要になった時点で純粋関数を別の皮で包み直す
- Vite の外で展開したくなったら、その時点で純粋関数を CLI に包む

## 影響

- ADR-0002 の責務の範囲（展開と集約まで、最適化は持たない）はそのまま有効
- ADR-0015 のパッケージ一覧から `@flat-html/core` を外し、`@flat-html/vite` に統合する
