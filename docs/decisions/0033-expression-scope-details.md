# ADR-0033: 引数と式の細目（透過する引数の判定、生テキスト要素、資産の slot、`undefined`）

- 状態: 採択（ADR-0010 / ADR-0012 / ADR-0023 を補う。置換はしない）
- 日付: 2026-11-02

## 文脈

コードレビューで、引数と式の扱いに、既存の決定を破るか、既存の決定からは導けない振る舞いが 4 つ見つかった。

- 透過しない引数を、描画で実際に評価された参照で決めていた。`<div><template if="show"><h2>{{ title }}</h2></template></div>` で `show` が偽だと、`title="T"` が `<div title="T">` に漏れる。`{{ a || b }}` で `a` が真のときの `b` も同じ。同じテンプレートでも、引数の値によって根要素に付く属性が変わる
- `<script>` と `<style>` の中の `{{ }}` も展開していた。parse5 はこれらの要素の中身をエスケープせずに直列化するので、ADR-0012 の「`{{ }}` は常に HTML エスケープする」が成り立たない。`<script type="application/ld+json">{"name":"{{ t }}"}</script>` は、`t` に `</script><script>alert(1)</script>` を入れると `<script>` を抜け出す。中身に `{{` を含むインラインスクリプト（`function f(){{let a=1}}`）は、式の構文エラーでビルドが落ちる
- 資産の要素（ADR-0023 で根要素とみなさない `<link>` と `<script type="module">`）は、参照タグの引数を 1 つも受け取らなかった。参照タグに `slot="title"` を付けても、名前付きの `<slot>` へ入るのは根要素だけで、資産は名前なしの差し込みに回る。名前なしの `<slot>` がなければ捨てられ、部品の CSS が出力から消える
- 引数は常に文字列なので、`<flat-x open>` の `open` は空文字で、`<template if="open">` は偽になる。`==` は型も比べる（ADR-0023）ので、`open != null` は引数がないときも真になる。属性があるかを調べる書き方がなかった。`open != undefined` は書けたが、`undefined` は未定義の名前として `undefined` に評価されていただけで、同名の引数があるとその値を指した

## 決定

### 透過しない引数は、テンプレートの字面で決める（ADR-0010 を補う）

- テンプレートが式で使う引数を、描画の前にテンプレートの字面から集める。集めた名前と同名の引数は、根要素へ透過しない。それ以外の引数は従来どおり透過する
- テキストと属性値の `{{ }}`、`<template>` の `if` の式、`each` の `of` の右辺、`html` の式を、`<template if/each/html>` の中まで含めて構文解析し、パスの先頭の名前を集める。評価されない分岐（偽の `if`、空の `each`、`&&` と `||` の評価されない側）も数える
- 素の `<template>` の中身と、生テキスト要素（次節）の中身は数えない。描画で展開しないため。それらの要素自身の属性は数える
- `each` が導入する変数名と同名の引数も「使った」とみなす。透過しないだけなので、安全側に倒れる
- 字面の構文解析で誤りがあれば、評価されない分岐の式でも、テンプレートのパスと行を添えて失敗させる

### 生テキスト要素の中は展開しない（ADR-0012 を補う）

- 直列化で中身がエスケープされない要素（`<script>`、`<style>`、`<xmp>`、`<iframe>`、`<noembed>`、`<noframes>`、`<plaintext>`、`<noscript>`）の中のテキストは、`{{ }}` を展開せず書かれたまま出す
- どの要素が当たるかは、parse5 の直列化と同じ判定で決める。`<noscript>` は、解析と直列化でスクリプトを有効とみなす parse5 の既定に合わせて含める
- その要素自身の属性の `{{ }}` は従来どおり展開する。属性値は直列化でエスケープされる
- `<title>` と `<textarea>` の中は従来どおり展開する。中身はテキストとして解析され、直列化でエスケープされる

### 資産は参照タグの slot だけを受け取る（ADR-0023 を補う）

- 参照タグの `slot` 属性が根要素へ透過するとき、テンプレートの最上位にある資産の要素にも同じ `slot` 属性を付ける。資産は根要素と同じ差し込み先へ入る
- `slot` 以外の引数は、従来どおり資産へ透過しない
- 差し込みで `slot` 属性は外れ（ADR-0011）、資産はその後の集約で `<head>` へ移る（ADR-0013）

### `if` の真偽は JavaScript と同じ。属性があるかは `!= undefined` で調べる（ADR-0012 / ADR-0023 を補う）

- `<template if>` の真偽は、従来どおり JavaScript の真偽と同じにする。空文字は偽である
- `undefined` を、`null`、`true`、`false` と同じリテラルにする。同名の引数やデータがあっても、`undefined` はそれを指さない
- 引数があるかは `!= undefined` で調べる。`<flat-x open>` では真、`open` を書かない `<flat-x>` では偽になる

```html
<template if="open != undefined"><p>開いている</p></template>
```

## 理由

### 字面で決める

- 根要素に付く属性が、テンプレートだけで決まる。引数の値で出力の属性が変わらないので、テンプレートを読めば、どの引数が透過するかが分かる
- 描画で評価された経路で決めると、`show` を切り替えただけで、`title` が根要素に現れたり消えたりする。ADR-0010 の「テンプレートが使わない属性」は、テンプレートに書いたものについての規則として読む
- 数える範囲は、描画で評価されうる式をすべて覆う。数え過ぎた引数は透過しないだけで、出力を壊さない

### 生テキスト要素の中を展開しない

- 生テキスト要素の中身は、直列化でエスケープされない。展開すると、ADR-0012 の「`{{ }}` は常に HTML エスケープする」を守れない。展開した値が `</script>` を含めば、要素を抜け出して任意の HTML になる
- インラインスクリプトと CSS は、`{{` と `}}` を普通の構文として使う（ブロックの入れ子、オブジェクトリテラル）。展開しなければ、こうしたコードをそのまま書ける

### 資産に slot だけを渡す

- 資産は部品の一部で、根要素と一緒に動くべきである。名前付きの差し込みに渡した部品の CSS だけが消えるのは、書き手の意図と合わない
- 資産に引数を透過しないのは、参照側の `id` などが `<link>` に乗るのを避けるためだった（ADR-0023）。`slot` は差し込み先を決める属性で、差し込みで外れる

### `undefined` をリテラルにする

- `if` の真偽は JavaScript のままにする。`&&` と `||` は JavaScript と同じく被演算子を返す（ADR-0023）ので、`if` だけ別の真偽にすると、同じ式が `if` と `{{ }}` で違う意味になる
- 書かれていない引数は `undefined` に、書かれた引数は文字列（値のない属性は空文字）になる。`==` は型も比べる（ADR-0023）ので、`!= undefined` が「属性があるか」をちょうど表す
- リテラルにしなければ、`undefined` は名前の解決に頼り、`undefined="…"` という引数やデータの `undefined` があるとその値を指す。リテラルにすれば、どの文脈でも同じ意味になる
- 足すのはリテラル 1 つで、演算子も構文も増えない。ADR-0012 の式の範囲に収まる

## 却下した選択肢

- 透過しない引数を、描画で実際に評価された参照で決める（従来の実装）: 引数の値で根要素の属性が変わる
- 生テキストの中は JavaScript や CSS 向けにエスケープして展開する: 文脈ごとのエスケープ（JSON の文字列、JavaScript の文字列、CSS の文字列など）を持つことになり、素朴でない
- 資産にもすべての引数を透過する: 参照側の `id` などが `<link>` に乗る。ADR-0023 で避けたことに戻る
- `if` を HTML の真偽属性と同じく、属性があれば真にする: `if="title"` で空の `title` を偽とみなせなくなり、`&&` `||` の JavaScript の意味とずれる

## 影響

- 評価されない分岐でしか使わない引数は、根要素へ透過しなくなる
- テンプレートの式の構文エラーは、評価されない分岐にあっても、そのテンプレートを展開するとビルドが失敗する。ページに書いた式は従来どおり、評価したときにだけ失敗する
- `<script>` や `<style>` の中に `{{ }}` を書いて値を埋めていたテンプレートでは、`{{ }}` が書かれたまま出る。値を渡すには、属性で渡すか、ビルドスクリプトで要素ごと組み立てて `<template html>` で差し込む
- 名前付きの差し込みに渡した部品の資産は、`<head>` へ集約されるようになる
- 参照タグが flat-html の差し込みの外で `slot` 属性を持つと（Custom Element の子として shadow DOM の `<slot>` へ投影する場合など）、資産も `slot` 属性を持ったまま `<head>` へ集約される。`<head>` の中の要素の `slot` 属性は描画に影響しない
- `undefined` という名前の引数やデータは、式から参照できなくなる
