# ADR-0024: 資産の解決はテンプレートの位置を基準にし、層の順序は各スタイルシートが宣言する

- 状態: 採択（ADR-0005 と ADR-0013 を補う）
- 日付: 2026-09-21

## 文脈

固有の CSS と JS を持つ最初のコンポーネント（明暗の切り替え、ADR-0022）を作って、骨格の決定に 2 つの穴が見つかった。どちらも実測で再現した。

### 穴 1: テンプレートが書いた資産の指定子が開発サーバーで解決されない

ADR-0013 は「テンプレートに普通の `<link>` と `<script>` を書き、解決は Vite の仕事」と決めた。しかし

- パッケージ名の指定子（`@flat-html/elements/color-scheme/index.css`）は、本番ビルドでは解決されるが、**開発サーバーでは書き換えられない**。ブラウザは `/pages/@flat-html/...` を要求し、HTML フォールバックが `text/html` の 200 を返すので資産として読み込まれない
- 相対パス（`./index.css`）は、テンプレートの位置ではなく**ページの位置**を基準に解決される

Vite の開発時 HTML 処理は、`/` で始まる・`.` で始まる・先頭が英数字のいずれでもない URL を書き換えない。`@` で始まる指定子はどれにも当たらない。

### 穴 2: 層の順序が読み込み順で決まり、束ね器の出力順に左右される

CSS の層の順序は「その名前が文書で最初に現れた順」で決まる。ADR-0005 は「層の順序は `flat.css` が 1 度だけ宣言する」としたが、コンポーネントの CSS が別のスタイルシートとして出力されると、束ね器がどちらを先に置くかで順序が変わる。

実測では、本番ビルドがコンポーネントの CSS を `flat.css` より**前**に出した。結果として文書全体の順序が `components, reset, base, site` になり、`components` 層が `base` 層に負けた。切り替え要素が一切効かなくなる。

## 決定

### 資産の解決

- **テンプレートとレイアウトに書かれた資産の URL は、そのファイルの位置を基準に解決する。** コンポーネントは自分の隣の資産を相対パスで指す（`./index.css`）
- パッケージ名の指定子も解決の対象にする
- `/` で始まる URL、スキームを持つ URL（`http:` `data:` など）は触らない
- ページ自身に書かれた資産は書き換えない。ページを基準にした解決は Vite が既にやっている
- 解決そのものは純粋関数 `transform` の中では行わず、呼び出し側が渡す関数（`resolveAsset(specifier, fromPath)`）に委ねる。ADR-0020 の「核は Vite に依存しない」を保つため。渡されなければ何も書き換えない
- 書き換えは集約より前に終える。重複除去の鍵は解決後の URL になり、別々のテンプレートが同じ資産を指しても 1 つにまとまる

これは ADR-0013 が「暗黙の動作は移動と重複除去の 2 つに限る」と書いた線を 1 つ広げる。広げる理由は、テンプレートの位置を知っているのがツールだけだからで、他の誰にも代われない。

### 層の順序

- **層を使うスタイルシートは、すべて冒頭で完全な順序を宣言する。** `@layer reset, base, components, site;`
- 宣言は冪等なので、何度繰り返しても順序は最初の 1 回で決まる。どのファイルが先に読み込まれても結果が同じになる

ADR-0005 の「層の順序は 1 箇所でだけ宣言する」は、スタイルシートが 1 つに束ねられる前提でしか成り立たなかった。順序の決め方自体は変えず、宣言を全ファイルに繰り返す。

## 却下した選択肢

- 束ね器の出力順を制御する: Vite の内部に踏み込むことになり、ADR-0020 の「公開 hook だけを薄く使う」に反する
- コンポーネントの CSS を層の外に置く: 層なしの規則はすべての層に勝つので、site 層からの上書き（ADR-0005 の逃げ道）が効かなくなる
- 層の順序を `@import` で 1 ファイルから取り込む: 束ねない状態でコンポーネントの CSS 単体が使えなくなる
- 消費側が各コンポーネントの CSS を手で読み込む: ADR-0013 の「使った分だけ載る」が失われる

## 引き受ける制約

縮小器が順序の宣言から一部の名前を落とすことがある。実測では `@layer reset, base, components, site;` が `@layer reset,base;` に縮んだ。その直後に `@layer components { … }` が続くので順序は保たれる。縮小器は順序の制約を壊さない範囲で削るため、結果は変わらない。
