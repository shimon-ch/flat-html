# ADR-0025: 公開は保留し、非公開のまま詰める

- 状態: 採択（ADR-0017 の「公開は見本サイトを GitHub Pages に出す時点」を置換）
- 日付: 2026-10-19

## 文脈

ADR-0017 は、最初の縦切りが通って見本サイトを GitHub Pages に出す時点でリポジトリを公開すると決めた。その時点が来たので公開の手順を確かめたところ、今のリポジトリを公開すると個人の Gmail アドレスが誰でも読める状態になることが分かった。

- main の履歴に、旧メールで作ったコミットが 9 個残っている
- PR 11 本の参照（`refs/pull/*/head`）が、旧メールのコミットを約 100 個保持している
- 公開されたリポジトリでは、コミットの URL の末尾に `.patch` を付けるだけで作者のメールが読める
- main の履歴を書き換えても PR の参照は消えない。GitHub の文書によると、PR の参照は読み取り専用で利用者は削除できず、GitHub サポートへの依頼が要る（[Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)）

所有者は GitHub で「メールを公開する push を拒否する」設定を有効にしており、このリポジトリの作者メールは 2026-10-19 から noreply に変えている。

## 決定

- **リポジトリは非公開のまま、中身を詰める。** 個人情報はなるべく公開しない
- 見本サイトの配信は止める。`pages.yml` の配信の段は、リポジトリ変数 `PAGES_DEPLOY` が `true` のときだけ走る。未設定のあいだは「飛ばした」扱いになり、ワークフローは失敗しない
- ビルドと Lighthouse の予算検査（ADR-0021）は main への push のたびに続ける

## 公開するときに要ること

公開の時期と方法は、そのときに改めて決める。少なくとも次を満たす。

- 旧メールが読めない状態で公開する。今のリポジトリをそのまま公開すると PR の参照から露出するので、作者メールを書き換えた履歴で新しいリポジトリを作り直す方法などを検討する
- コミットメッセージ、文書、成果物に、個人に結びつく情報が残っていないかを確かめる
- 公開の範囲（コード全体か、見本サイトだけか）を決める。見本サイトだけなら、リポジトリを非公開のまま別の配信先に出す方法もある
- Pages を有効にし、リポジトリ変数 `PAGES_DEPLOY` を `true` にする

## 却下した選択肢

- 今のリポジトリをそのまま公開する: 旧メールが公開される
- Pages のワークフローを丸ごと止める: Lighthouse の予算検査まで止まる
- 配信の段を失敗のまま放置する: main に常に赤い印が付き、本当の失敗が見分けにくくなる
