# ADR-0022: 明暗の切り替えは 3 状態のラジオグループ

- 状態: 採択（ADR-0014 の「切り替え要素は `<input type="checkbox" switch>` を基礎にする」を置換。他の項は有効）
- 日付: 2026-09-21

## 文脈

ADR-0014 は切り替え要素を `<input type="checkbox" switch>` と `:root:has(:checked)` で作ると決めた。実装に入って、2 状態では足りないことが分かった。

チェックなしが「システムに従う」、チェックありが「暗」だとすると、システムが暗い利用者は明を選べない。逆に振っても同じ非対称が反対側に出る。チェックボックスに「システムから反転する」という意味を持たせれば 2 状態で表せるが、利用者が持つ心的模型としては分かりにくい。

## 決定

- 切り替え要素は **3 状態のラジオグループ**にする。自動（システムに従う）、明、暗
- グループは `<fieldset>` と `<legend>` で囲む
- `:root:has(input[name="flat-color-scheme"][value="light"]:checked)` のような選択子で `:root` の `color-scheme` を上書きする。`@flat-html/css` の色はすべて `light-dark()` なので、`color-scheme` を変えるだけで全体が追従する（ADR-0014）
- JS が足すのは選択の保存と次ページ以降への引き継ぎだけ（ADR-0004 の 3 項）
- Open UI の Switch 属性はこのコンポーネントでは使わない

## 理由

- 3 状態は、利用者が実際に持つ選択肢（システムに任せる / 明にする / 暗にする）とそのまま対応する
- ラジオグループはネイティブに矢印キーでの移動とグループ名の読み上げがあり、APG の Radio Group の要件を JS なしで満たす。ADR-0003 の場合分けで「JS を持たない」側に収まる
- `<fieldset>` と `<legend>` は「これは 1 つの選択である」ことをマークアップで表す。ADR-0005 の「セマンティクスを最優先する」と一致する

## 却下した選択肢

- `<input type="checkbox" switch>` の 2 状態: 上の非対称が残る
- チェックボックスに「システムから反転」の意味を持たせる: 心的模型が悪い
- `<select>` による 3 状態: 選択肢が 3 つなら常に見えているラジオの方が操作が短い

## 引き受ける制約

選択の復元は JS が読み込まれてから起きる。資産は `<head>` に集約されるが `<script type="module">` は遅延実行なので、保存された選択が反映されるまでの一瞬、既定の配色が見える。これを消すには描画を止める同期スクリプトが要り、ADR-0013 の「新しい語彙を作らない」と初回描画の速さの両方を損なう。一瞬の色の変化はレイアウトシフトではないので ADR-0021 の CLS の予算には影響しない。
