# ADR-0027: npm への公開は見送り、配布の手段は個人サイトで使い始めるときに決める

- 状態: 採択（ADR-0001 の「個人サイトは npm 経由で消費する」を保留に置換）
- 日付: 2026-10-20

## 文脈

ADR-0001 は、個人サイトを別リポジトリに置き、ライブラリ群を npm 経由で消費すると決めた。

見本サイト `apps/site` は、同じリポジトリの中から `workspace:*` で手元のパッケージを参照する。npm に公開しなくても、ビルドも配信もできる。npm への公開が要るのは、別のリポジトリから使うときだけである。

npm に公開すると、次のものを誰でも読める。

- パッケージの中身。`@flat-html/vite` は `dist`、`@flat-html/css` と `@flat-html/elements` は `src`
- 公開したアカウントの名前とメールアドレス。レジストリの公開情報（`maintainers` と `_npmUser`）に載る。公開中のパッケージの情報で確かめた
- `package.json` の `repository`。今は非公開のこのリポジトリを指す

ADR-0025 は、個人情報をなるべく公開しないと決めている。

## 決定

- 今は npm に公開しない
- 個人サイトでライブラリ群を使い始めるときに、配布の手段を決める。候補は次の 4 つ
  - npm に公開する
  - GitHub Packages に非公開で置く
  - git のリポジトリから直接入れる
  - 個人サイトをこのリポジトリに入れる（ADR-0001 の見直しになる）
- 比べる観点は、表に出る個人情報、料金、個人サイトの CI がこのリポジトリを読むための認証、`@flat-html/vite` のビルド済みファイルを渡せるか

## 理由

- 別のリポジトリの利用者が、今はいない。公開しても得るものがなく、個人情報が表に出る
- 候補ごとの料金と認証の手間を、まだ一次情報で確かめていない。使い始める時点の条件で比べるほうが確か

## 却下した選択肢

- 今 npm に公開する: アカウントのメールアドレスとリポジトリ名が表に出る。公開の準備も済んでいない（影響を参照）

## 影響

- `publishConfig.access: public` と `repository` は今のまま残す。npm に公開すると決めたら見直す
- 見本サイトは手元のフォルダを参照するので、包みの中身に漏れがあっても見本サイトのビルドでは見つからない
- npm に公開すると決めたら、少なくとも次を済ませる
  - 個人に結びつかないメールアドレスで npm アカウントを用意する
  - `@flat-html/vite` は包みに `dist` しか入らないのに、包む前にビルドする仕組み（`prepack` など）がない。ビルドを忘れると、中身のないパッケージが出る
  - `@flat-html/elements` の包みにテスト（`*.test.ts`）と `spec.md` が入る。入れるかを決める
  - `@flat-html/vite` と `@flat-html/elements` に README を足す
  - 版番号を 0.0.0 から上げる
