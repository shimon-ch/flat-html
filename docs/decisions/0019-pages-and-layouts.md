# ADR-0019: ページは完全な HTML 文書、レイアウトは `<link rel="layout">`

- 状態: 採択
- 日付: 2026-09-10

## 文脈

ページとレイアウトの関係をどう書くか。`<flat-layout>` で本文を包む形は語彙を増やさないが不格好。コメント指示 `<!-- @flat layout="…" -->` は Server Side Includes（NCSA HTTPd、`<!--#include -->`）の先例があり、ツールを通さなくても有効な HTML のままだが、コメントが振る舞いを持つと読み手の期待を裏切り、道具の支援もない。

SSI の本質は「ページは完全な文書のまま、一部だけ置き換える」こと。SSI がコメントに隠したのは当時 `<link>` の慣習がなかったからで、今なら要素で書ける。

## 決定

- ページは完全な HTML 文書として書く（doctype から `</html>` まで）
- レイアウトは `<head>` の `<link rel="layout" href="…">` で宣言する
- flat-html の合流規則
  - ページの `<head>` の子要素をレイアウトの `<head>` へ合流させる
  - ページの `<body>` の子要素をレイアウトの `<body>` にある `<slot>` へ移す
  - `<html>` と `<body>` の属性をレイアウト側へ合流させる
  - `<link rel="layout">` 自体は出力から消す
  - `<title>` の重複はページが勝つ。`<meta charset>` と `<meta name="viewport">` は 1 つに揃える。それ以外の重複規則は実装時に定める
- 種類は文書構造で決める。`<html>` を持つものがページ、ページのうち `<body>` に `<slot>` を持つものがレイアウト、`<html>` を持たない断片がコンポーネント
- 継承の語彙（`extend`、`block`）は持たない。多段にしたければレイアウトの中で別のレイアウトを参照する
- 名前解決は探索先を複数並べて先頭から探す。どの探索先から解決されたかを一覧で出力する

## 理由

- 新しい構文がゼロ。`<link rel>` は文書間の関係を表す標準要素で、`rel` の値は拡張前提（`canonical`、`alternate`、かつての `import`）
- ページ単体でブラウザに開ける。SSI の「無効でも壊れない」を、コメントでなく文書構造で達成する
- 題名は `<title>` がそのまま合流するので引数が要らない。レイアウトが知りたい情報は `<meta>` や `<html>` の属性として HTML の語彙で書ける
- 島の初期データ `<script type="application/json">` も `<head>` に書けば合流で届く

## 却下した選択肢

- `<flat-layout>` で包む: 不格好だが成立する。コメント指示と並ぶ代替として記録する
- コメント指示: 読み手の期待、道具の支援、誤字の黙殺
- ディレクトリの既定レイアウト: 暗黙の動作
- `extend` と `block`: 差し込みと継承の 2 つの心的模型を強いる
- header.html と footer.html の半端な分割（SSI 流）: `parse5` が半端な文書を扱えない

## 影響

- 各ページに doctype から body までの定型が付く
- 合流規則の細部は実装時に ADR を追加して定める
- 将来の案として、`<link rel="import">` をビルド時に復活させ、ページやレイアウトが使うコンポーネントを `<head>` で明示的に宣言する形を記録しておく。探索先の暗黙の解決が問題になったときの逃げ道
