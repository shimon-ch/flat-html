# 用語集

このリポジトリの文書と仕様で使う語。ここにない語は使う前にここへ足す。

| 語 | 意味 |
|---|---|
| **素朴** | 標準がすでに持つものを使い、具体的な必要が出るまで足さないこと。思想の中心 |
| **flat-html** | HTML の解析から変換までを担う npm パッケージ（`@flat-html/core`）。展開と集約のみ行う。Rust は速度のための内部実装であり、crates.io には出さない |
| **展開** | テンプレートの参照を、ビルド時に完全な HTML へ置き換えること。1 回の走査で行い、結果を再走査しない |
| **集約** | 展開後の `<link>` と `<script>` を `<head>` へ移し、同じ URL の重複を除くこと |
| **差し込み** | 消費側の子要素をテンプレートの `<slot>` の位置へ移すこと。shadow DOM の投影と違い、要素を実際に移動する |
| **合流** | ページの `<head>` の子と `<html>` `<body>` の属性を、レイアウトの同じ場所へまとめること |
| **参照** | テンプレートの中で別のコンポーネントをタグ名で呼ぶこと。`<flat-accordion>` など |
| **引数** | 参照タグの属性。テンプレートが使わないものは出力の根要素へ透過する |
| **コンポーネント** | `<html>` を持たない HTML の断片。テンプレート、固有 CSS、必要なら JS で構成される |
| **ページ** | `<html>` を持つ完全な HTML 文書 |
| **レイアウト** | `<body>` に `<slot>` を持つページ。他のページから `<link rel="layout">` で参照される |
| **出力の根要素** | 展開後にテンプレートが出力する最上位要素。複数ありうる。すべてに `data-flat` が付く |
| **仕様 4 項** | 各コンポーネントが必ず書く「目的 / JS なしで到達できる状態 / JS が足す強化 / 出力の根要素」 |
| **JS なしで到達できる状態** | Custom Element の定義モジュールを読み込まない状態で、HTML だけで成立する目的の範囲 |
| **アップグレードギャップ** | HTML が描画されてから Custom Element の定義が到着し適用されるまでの時間 |
| **無害化** | アップグレードギャップを消すのではなく、その間も壊れて見えないようにすること |
| **逆流** | 消費側（サイト）の都合がライブラリやツールに漏れること |
| **見本サイト** | `apps/site`。ライブラリ群の使用例を示す文書サイト。GitHub Pages に出す。公開パッケージではない |
| **探索先** | 参照名からテンプレートのファイルを探すディレクトリの並び。先頭から探す |
| **APG** | ARIA Authoring Practices Guide。各 UI のキーボード操作とフォーカス管理の要件の出典 |
| **Open UI** | ブラウザに欠けている UI をネイティブ化する提案群。卒業済みの提案はネイティブ扱いとする |
| **Baseline** | 主要ブラウザすべてで使える状態。CSS と HTML の機能採用の基準 |
